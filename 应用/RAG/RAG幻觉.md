# RAG幻觉

RAG（检索增强生成）虽然能显著缓解大语言模型（LLM）的幻觉问题，但并不能完全消除幻觉。幻觉可能在 RAG 流程的输入、检索、排序、输出等多个阶段产生。

从用户将文档输入到RAG中入库，到检索以及最后的输出任何一部都会导致RAG产生幻觉。

## 数据准备

原因：数据准备阶段准备的数据质量低下。

1. 源数据的过时或错误。
2. 切分粒度不当导致语义断裂。

解决方案：

1. 语义切分，按照段落/意群切分
2. 元数据增强，为chunk打上标签说明出处。
3. 定时更新数据库中的数据，并选择较为权威的数据源。

## 查询优化

幻觉原因：

* 模糊/歧义查询：如“那个红色的东西” → LLM 可能脑补错误实体
* 隐含错误前提：如“为什么地球是平的？” → 引导模型接受错误事实
* 缺少上下文：多轮对话中指代不明

模型为了强行回答用户的问题就会开始胡扯一通。

解决方案：

| 方法 | 说明 |
|------|------|
| 查询澄清（Query Clarification） | 让 LLM 主动追问：“您指的是哪款红色产品？” |
| 查询重写（Query Rewriting） | 用历史上下文改写查询：<br>`"那个红色的东西" → "上周提到的红色 iPhone"` |
| 前提验证 | 检测并拒绝错误前提：<br>“地球并非平的，它是近似球体。” |

## 检索与召回

幻觉原因：

* 向量相似但语义无关：向量相似度高 ≠ 语义相关（如“苹果公司” vs “水果苹果”）
* 专有名词难以检索（Recall），比如我要找龙芯2k1000 但是用向量检索可能会找到 2k500。这里就找错了。

解决方案：

| 方法 | 说明 |
|------|------|
| 混合检索（Hybrid Search） | 结合关键词（BM25） + 向量（Embedding）提升召回率 |
| 多路召回 | 同时从多个知识库检索（技术文档 + 新闻 + 论文） |

## 重排序

幻觉原因：

* 检索阶段召回了大量的文档（top50），文档中可能包含了大量的无关信息。
* 在大量的文档中可能只有3和48是有效的，这样就会造成模型产生迷失中间的现象，被召回的噪声干扰。
* 关键证据被过滤：重要但向量距离稍远的片段被丢弃

解决方案：

| 方法 | 说明 |
|------|------|
| Cross-Encoder 重排 | 用 BERT 类模型计算 query-chunk 的精细相关性 |
| LLM 重排 | 让 LLM 判断：“这段是否回答了问题？” |
| 去重与过滤 | 移除重复、广告、模板化内容 |
| 置信度过滤 | 设定阈值，低于则返回“未知”而非强行回答 |

## 输出阶段

幻觉原因：

* LLM 忽略检索结果：过度自信，用自己的知识覆盖检索内容。
* 错误整合信息：将多个片段矛盾信息拼接成“新事实”
* 过度泛化：从局部证据推出全局结论（如“某实验成功” → “该疗法已普及”）

| 方法 | 说明 |
|------|------|
| 强提示工程 | 明确指令：<br>`“仅基于以下上下文回答，若无相关信息请说‘我不知道’”` |
| 思维链+引用溯源（Citation） | 要求 LLM 标注答案来源：<br>`“根据[1]，准确率为94.5%”` |
| 不确定性感知 | 当检索结果弱相关时，输出概率化表述：<br>`“可能”、“据某报告显示”` |
|SFT微调|强化模型对Context的忠实度|
