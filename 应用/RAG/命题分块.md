# 命题分块增强RAG

命题分块增强 RAG（Proposition-based Chunking for RAG）是一种改进传统文本分块方式的检索增强生成（RAG）技术，其核心思想是：将文档按“语义命题”而非固定长度或句子边界进行切分，从而提升检索的相关性和生成质量。

**命题分块增强 RAG**（Proposition-based Chunking for RAG）是一种**改进传统文本分块方式**的检索增强生成（RAG）技术，其核心思想是：**将文档按“语义命题”而非固定长度或句子边界进行切分**，从而提升检索的相关性和生成质量。

## 传统 RAG 的问题：为什么需要改进分块？

在标准 RAG 中，文档通常被**机械地按字符数或句子数切分**（如每 512 字一段），这会导致：

| 问题 | 举例 |
|------|------|
| ❌ **语义割裂** | “苹果公司成立于1976年，由史蒂夫·乔布斯等人创立。” 被切成两段，丢失完整事实 |
| ❌ **噪声混入** | 一段包含多个无关主题（如同时讲 AI 和天气），降低检索精度 |
| ❌ **关键信息稀释** | 重要事实淹没在长段落中，向量表示不聚焦 |

**结果**：检索到的“相关段落”可能不包含完整答案，LLM 无法准确回答。

## 命题分块（Proposition-based Chunking）怎么做？

### ✅ 核心思想

![alt text](image-1.png)

> **把每个独立、完整的“事实性陈述”作为一个分块单元**，称为一个 **命题**（Proposition）。

一个命题 = 一个可独立验证的语义单元（通常是一个简单句或子句）。

### 🔧 实现步骤

1. **文档解析**  
   输入原始文档（如 PDF、网页、报告）

2. **语义分解**  
   使用 LLM 或规则将段落拆解为原子命题。例如：

   **原文**：  
   > “特斯拉成立于2003年，总部位于美国得克萨斯州。其CEO埃隆·马斯克同时也是SpaceX的创始人。”

   **命题分块后**：
   - 块1: “特斯拉成立于2003年。”
   - 块2: “特斯拉总部位于美国得克萨斯州。”
   - 块3: “埃隆·马斯克是特斯拉的CEO。”
   - 块4: “埃隆·马斯克是SpaceX的创始人。”

3. **向量化 & 存储**  
   每个命题单独生成 embedding，存入向量数据库

4. **检索 & 生成**  
   用户提问 → 检索最相关的**若干命题** → 拼接为上下文 → LLM 生成答案

### 示例效果

- **用户问**：“谁是特斯拉的CEO？”
- **传统 RAG**：可能召回整段含 CEO 的长文本，也可能因分块不当漏掉
- **命题 RAG**：直接命中命题3，精准提供答案

## 为什么需要命题分块？—— 优势总结

| 优势 | 说明 |
|------|------|
| ✅ **高检索精度** | 每个块只包含一个事实，避免无关信息干扰 |
| ✅ **减少幻觉** | LLM 基于明确事实生成，不易编造 |
| ✅ **支持细粒度问答** | 能回答具体细节问题（如“成立时间？”、“总部在哪？”） |
| ✅ **提升向量表示质量** | 向量聚焦单一语义，相似度计算更准确 |
| ✅ **兼容复杂文档** | 适合技术文档、法律条文、研究报告等高信息密度文本 |

## 技术实现方式（如何生成命题？）

1. **基于 LLM 的分解**（主流）

   ```python
   prompt = f"""
   将以下段落分解为独立、简洁的事实性陈述（每句一个事实）：
   段落：{text}
   输出格式：每行一个命题，不要编号。
   """
   propositions = llm(prompt).split('\n')
   ```

2. **基于依存句法分析**（NLP 工具）
   - 使用 spaCy、Stanford CoreNLP 提取主谓宾结构
   - 适用于结构化强的文本

3. **混合方法**
   - 先用规则粗分，再用 LLM 精炼

## 适用场景

- 📚 **知识库问答系统**（如企业知识库、客服机器人）
- 📊 **研究型 RAG**（需精确引用数据、结论）
- ⚖️ **法律/医疗文档分析**（事实准确性至关重要）
- 🤖 **AI Agent 记忆存储**（将用户对话提炼为命题记忆）

### ✅ 总结

> **命题分块增强 RAG 通过“以事实为单位”切分文档，解决了传统分块的语义割裂问题，显著提升了检索的精准度和生成答案的可靠性。**  
> 它不是替换 RAG，而是**优化 RAG 的前端预处理环节**，让“检索到的内容”真正包含“能回答问题的信息”。
> 💡 正如论文《**Lost in the Middle**》所揭示：**信息的位置和粒度，直接影响 LLM 的表现** —— 命题分块正是对此的优雅回应。
