# LLM规划阶段大纲质量不稳定的解决方案

核心逻辑：先通过“分层定位”找到大纲质量不稳定的核心环节，再结合项目现有技术栈（LangGraph、LLM、知识库），针对性做“输入约束、过程管控、输出校验”，最终联动审核Agent形成闭环，彻底解决不稳定问题，贴合项目中“三级质量评估”和“多Agent协同”的设计理念。

## 一、第一步：定位问题（先明确“哪里出问题”，面试必说，体现排查思维）

首先要明确：大纲质量不稳定的核心表现的是「不符合用户需求、逻辑混乱、覆盖不全、重点偏移」，需从“输入→LLM本身→输出校验→外部依赖”4个维度分层定位，避免盲目优化，具体定位方法如下：

### 1. 明确质量不稳定的具体表现（先量化/具象化问题）

- 需求匹配度低：大纲偏离用户输入的行业、研究范围（比如用户要“新能源汽车充电桩行业”，大纲生成“新能源汽车整车”）；

- 逻辑不连贯：章节层级混乱（比如先写“市场规模”，再写“行业定义”），无明确递进关系；

- 覆盖不全：遗漏核心模块（比如行业研究必备的“竞争格局”“发展趋势”缺失）；

- 冗余/空洞：章节重复（多次出现“政策影响”），或大纲过于笼统（仅写“市场分析”，无细分维度）；

- 时效性偏差：大纲包含过时研究维度（比如传统行业仍重点写“疫情影响”），未贴合当前行业热点。

### 2. 分层定位问题环节（结合项目实际，可落地排查）

通过“日志回溯+对照测试”，锁定3个核心易出问题的环节（优先级从高到低）：

1. 输入环节：用户需求模糊/未被有效解析，规划Agent未获取到关键约束（行业、范围、深度、时效）；

2. LLM生成环节：Prompt无标准化约束、未结合行业知识库、采样参数不合理，导致生成随机性强；

3. 输出校验环节：规划阶段未做前置校验，直接将不合格大纲传入下一个Agent（搜索Agent），导致问题放大。

补充：排除外部依赖问题（如LLM接口超时、知识库检索异常），这类问题可通过项目现有Checkpoint机制、重试机制兜底，不属于大纲质量本身的不稳定因素。

## 二、第二步：针对各环节的优化方案（贴合项目技术栈，面试突出“落地性”）

优化核心：围绕“减少LLM生成的随机性、强化约束、前置校验”，联动项目现有架构（LangGraph工作流、Milvus向量库、三级质量评估），不新增额外技术成本，确保和原有系统兼容。

### 环节1：输入优化——解决“用户需求模糊，规划Agent无明确约束”

核心目标：将模糊需求转化为“标准化输入参数”，让规划Agent（LLM）明确“写什么、写多深、覆盖哪些维度”，从源头降低随机性。

1. 用户需求结构化拆解（前端+后端联动）

    - 前端增加“需求录入表单”：用户提交研究需求时，必须选择「行业分类」「研究深度」（基础/深度）「核心关注点」（可多选：市场规模、竞争格局、政策、趋势等）「时效要求」（近1年/近3年）；

    - 后端做需求归一化处理：将用户输入的自然语言（如“帮我分析一下充电桩行业”），结合表单参数，转化为标准化Prompt前缀，例如：“请生成「新能源汽车充电桩行业」的深度研究大纲，核心覆盖市场规模、竞争格局、政策支持、未来趋势4个维度，仅聚焦近1年的信息，章节层级清晰，无冗余、无遗漏”。

2. 规划Agent增加“需求解析前置步骤”

    - 在LangGraph工作流中，给规划Agent增加“前置解析节点”：先通过轻量LLM（或规则引擎）解析用户需求+表单参数，提取核心约束，生成“约束清单”，再将约束清单传入生成大纲的LLM；

    - 举例：约束清单=「行业：充电桩；深度：深度；核心模块：4个；时效：近1年；层级：至少3级（一级章节→二级小节→三级要点）」。

### 环节2：LLM生成优化——解决“Prompt无约束、生成随机性强”（核心优化环节）

结合项目现有技术栈（LangGraph、Milvus向量库），重点做3点优化，兼顾稳定性和灵活性：

1. 标准化Prompt模板（核心，减少随机性）

    - 摒弃“开放式Prompt”，设计固定模板，包含「角色定义、约束条件、输出格式、参考示例」4个核心部分，示例：
                角色：你是专业的行业研究规划师，擅长生成逻辑清晰、覆盖全面的研究大纲。
    约束条件：1. 严格贴合「充电桩行业」，不偏离范围；2. 核心覆盖市场规模、竞争格局、政策支持、未来趋势4个模块，不遗漏；3. 章节层级≥3级，逻辑递进（行业定义→现状→核心分析→趋势）；4. 不冗余、不空洞，每个二级小节需明确具体研究要点；5. 仅聚焦近1年信息。
    输出格式：一级章节（加粗）→ 二级小节 → 三级要点，用有序列表呈现，无多余描述。
    参考示例：一、行业概述（1.1 行业定义；1.2 行业发展历程；1.3 近1年行业整体态势）；二、市场规模分析（2.1 整体市场规模；2.2 细分领域规模；2.3 规模增长驱动因素）……

    - 模板动态适配：根据用户选择的「行业」「研究深度」，通过规则引擎替换模板中的约束条件和参考示例（比如基础深度仅需2级层级，深度研究需3级）。

2. 结合Milvus向量库，引入“行业大纲参考案例”（降低幻觉，提升一致性）

    - 预处理：收集各行业高质量研究大纲（人工整理+优质报告提取），进行Embedding后存入Milvus向量库，关联「行业分类」「研究深度」标签；

    - 生成大纲前，规划Agent先通过Milvus语义检索，召回3-5份同行业、同深度的优质大纲案例，作为LLM生成的参考（Prompt中加入：“参考以下优质大纲的结构和维度，生成符合约束条件的大纲，不直接复制，保证原创性”）；

    - 优势：利用项目现有向量库资源，无需新增组件，同时让大纲结构贴合行业惯例，减少逻辑混乱的问题。

3. LLM参数调优（降低生成随机性）

    - 调整核心参数：降低温度值（temperature）至0.3-0.5（默认通常0.7，值越低，生成越确定、越严谨，适合结构化大纲生成）；

    - 固定种子值（seed）：针对同一类需求（同行业、同深度），使用固定种子值，确保生成的大纲结构一致性；

    - 限制输出长度和格式：通过max_tokens限制大纲长度，同时指定输出格式（有序列表、层级区分），避免LLM生成多余内容或格式混乱。

4. LangGraph工作流中增加“多轮迭代生成”（贴合项目工作流）

    - 将规划Agent的生成逻辑改为“生成→自检→修正”的小闭环（LangGraph中新增自检节点）；

    - 自检逻辑：LLM根据前置的“约束清单”，自我检查大纲是否符合要求（比如是否遗漏核心模块、层级是否足够），若不符合，自动修正后输出；

    - 兜底：若自检2次仍不符合，触发“人工介入提示”（通过SSE推送给用户，或通知管理员），避免不合格大纲流入下一个Agent。

## 环节3：输出校验优化——解决“无前置校验，问题放大”

核心目标：在规划阶段结束后、搜索Agent启动前，新增“大纲质量前置校验”，将不合格大纲拦截，避免后续搜索、分析Agent做无用功，同时联动项目“三级质量评估体系”。

1. 搭建“大纲质量自动化校验规则”（对应三级评估中的“自动化指标”）

    - 核心校验指标（可量化、可自动化）：

        - 需求匹配度：校验大纲核心模块是否与用户选择的“核心关注点”完全匹配（规则引擎比对，比如用户选了4个模块，大纲必须全部包含）；

        - 层级完整性：校验章节层级是否达到要求（基础深度≥2级，深度研究≥3级）；

        - 无冗余性：校验是否有重复章节（字符串比对，重复率≤5%）；

        - 时效性：校验大纲中是否包含“近1年”“最新”等时效相关表述，或核心模块是否贴合时效要求（通过关键词比对）。

    - 校验逻辑：自动化校验通过（所有指标达标），大纲进入下一个Agent（搜索Agent）；未通过，返回规划Agent重新生成（最多重试2次），重试仍失败则触发人工评审（对应三级评估中的“人工评审”）。

2. 引入“LLM辅助评分”（对应三级评估中的“LLM辅助评分”）

    - 自动化校验通过后，新增LLM辅助评分节点：让专门的评分LLM（与生成大纲的LLM区分，避免同源偏差），对大纲的“逻辑连贯性、覆盖全面性、行业适配性”打分（满分100分，阈值80分）；

    - 评分≥80分：正常流转；＜80分：返回规划Agent，结合评分反馈（比如“逻辑连贯性不足，建议调整章节顺序”）进行修正；

    - 优势：复用项目现有三级质量评估体系，无需新增评估模块，同时提升大纲质量的稳定性。

### 环节4：兜底优化——解决“极端场景下的不稳定”（面试加分项，体现严谨性）

1. 建立“大纲模板库”：针对高频行业（如新能源、半导体），人工整理优质固定大纲模板，当LLM生成多次不合格时，直接调用对应行业的模板，替换变量（如时效、细分领域），快速生成合格大纲；

2. Checkpoint机制联动：将大纲生成的每一步（约束清单、参考案例、生成版本、校验结果），通过Checkpoint机制持久化到PostgreSQL JSONB字段，若大纲生成失败，可快速恢复到上一步，无需重新解析需求、检索案例，提升效率；

3. 持续迭代优化：将所有不合格大纲、用户反馈的问题大纲，整理成“负面案例库”，定期优化Prompt模板、校验规则和LLM参数（比如某类行业大纲频繁遗漏“竞争格局”，则在Prompt中强化该模块的约束），形成“生成→校验→反馈→优化”的闭环（贴合项目“数据采集→质量监控→持续改进”的闭环设计）。

## 三、第三步：优化效果验证（面试必说，体现结果思维，贴合项目成果）

优化后，可通过3个维度验证效果，贴合项目中“量化成果”的风格：

1. 质量稳定性：大纲合格率从优化前的70%以下，提升至90%以上（与项目整体报告通过率一致）；

2. 用户匹配度：用户对大纲的修改需求降低80%，无需频繁调整大纲结构；

3. 效率提升：规划阶段大纲生成时间缩短，无需多次重试，整体报告生成的端到端时间（5-10分钟）不受影响，甚至略有提升。

## 四、面试答题总结（提炼核心，简洁好记）

核心思路：先通过“输入→生成→输出”分层定位大纲质量不稳定的核心环节，再围绕“强化约束、降低随机、前置校验”，复用项目现有LangGraph工作流、Milvus向量库、三级质量评估体系，从源头（需求结构化）、核心（标准化Prompt+案例参考）、兜底（校验+闭环迭代）三个层面优化，最终实现大纲质量稳定，同时贴合项目整体设计，不新增技术成本，兼顾稳定性和效率。
